## 1. 测试概述

### 1.1 测试目的

本报告针对「二手交易平台」项目的核心业务模块开展自动化测试，用于验证：

- 各业务模块**模型层**的字段约束、默认值、外键关联与唯一性约束是否正确；
- 各**视图层**功能（注册、登录、商品发布/浏览、购物车、订单、收藏、消息）是否按预期工作；
- **权限控制**（登录保护、数据隔离）是否可靠；
- 是否存在隐藏缺陷。

### 1.2 测试范围

- **范围内（In Scope）**：用户、商品、购物车、订单、收藏、消息 6 大业务模块及首页。
- **范围外（Out of Scope）**：后台管理界面（SimpleUI）的手工测试、性能测试、安全渗透测试、浏览器兼容性测试。

## 3. 测试策略与方法

- **单元测试（白盒）**：针对模型层，验证 `__str__`、默认值、`unique_together` 唯一约束、外键关联等；
- **功能测试（黑盒）**：使用 Django 测试客户端（`self.client`）模拟 HTTP 请求，验证状态码、重定向、模板上下文数据；
- **鉴权测试**：验证 `@login_required` 页面的未登录跳转，以及数据隔离（用户只能看到自己的购物车/订单/收藏/消息）；
- **异常与边界测试**：验证不存在资源返回 404、重复记录抛出 `IntegrityError` 等。

测试数据在每条用例前通过 `setUp` 创建；文件上传使用 `SimpleUploadedFile` 并配合 `@override_settings(MEDIA_ROOT=临时目录)` 隔离，保证不污染真实数据。

## 6. 缺陷记录

| 编号 | 缺陷描述 | 严重程度 | 状态 | 修复方案 |
| --- | --- | --- | --- | --- |
| BUG-001 | `@login_required` 未配置 `LOGIN_URL`，未登录用户访问受保护页面被重定向到不存在的 `/accounts/login/`，导致 404 | 中 | 已修复 | 在 `settings.py` 中增加 `LOGIN_URL = 'users:login'` |
| BUG-002 | Python 3.14 与 Django 4.2 不兼容，测试渲染模板时报 `Context.__copy__` 错误 | 高（环境） | 已解决 | 统一使用 Python 3.8～3.12（本项目为 3.11），测试改用 SQLite |
